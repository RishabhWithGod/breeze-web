# Realtime architecture

Laravel Reverb + Laravel Echo, wired for the handful of screens where a
manual refresh would actually be noticed: Job Detail, Job Schedule, the AI
Takeoff Processing screen, the notification bell, and the always-visible
timer indicator. Everything else in the app stays exactly as it was —
Inertia props on navigation, no socket involved.

```
Laravel Event  →  Broadcasting  →  Reverb (WebSocket)  →  Echo (browser)  →  React
```

The database is always the source of truth. A broadcast never carries state
that doesn't already exist in MySQL — every event class in `app/Events/`
fires *after* the write that produced it has committed (see
[Database-first broadcasting](#database-first-broadcasting) below) — and the
browser never trusts a socket message on its own: receiving one only ever
triggers either a small Inertia partial reload (`router.reload({ only:
[...] })`) of the real props, or, for the AI Takeoff screen, applies a
payload shaped identically to what the existing long-poll endpoint already
returns. Losing the connection loses nothing; it just stops being told
about changes early.

## Why Reverb

The app had no broadcasting infrastructure at all before this (`BROADCAST_
CONNECTION=log`, no `routes/api.php`, no Sanctum). Reverb was the
correct default rather than an arbitrary choice: it's first-party Laravel,
speaks the Pusher protocol (so `laravel-echo`/`pusher-js` need no
Reverb-specific code on the frontend), and runs as a normal artisan command
next to the existing `queue:work` process — no new infrastructure class
(Redis pub/sub, a separate Node service) to operate.

## Local development setup

```bash
cp .env.example .env   # if you haven't already
php artisan key:generate

# Reverb needs its own app credentials — these are already generated for
# local dev in a fresh .env.example; for a new environment:
php artisan reverb:install   # only if config/reverb.php + routes/channels.php don't exist yet

# Three long-running processes, alongside `php artisan serve` and `npm run dev`:
php artisan reverb:start
php artisan queue:work
```

`composer.json`'s `dev` script already bundles `queue:work`; it does not yet
start Reverb — see [Production Reverb process](#production-reverb-process)
for why that's a separate, supervised process rather than something folded
into a dev convenience script.

## Environment variables

| Variable | Meaning | Example (local) |
| --- | --- | --- |
| `BROADCAST_CONNECTION` | Must be `reverb` for realtime to actually broadcast. `log`/`null` disables it silently (see [Testing](#testing-and-the-null-driver)). | `reverb` |
| `REVERB_APP_ID` / `REVERB_APP_KEY` / `REVERB_APP_SECRET` | The app's Reverb credentials. `SECRET` signs private-channel auth responses — **never** send it to the frontend. | generated by the installer |
| `REVERB_SERVER_HOST` / `REVERB_SERVER_PORT` | What `reverb:start` actually binds to on *this machine*. | `0.0.0.0` / `8080` |
| `REVERB_HOST` / `REVERB_PORT` / `REVERB_SCHEME` | The **public** address a browser connects to. Behind a reverse proxy these are deliberately different from the server bind above — see [Production](#production-environment). | `localhost` / `8080` / `http` |
| `REVERB_APP_ALLOWED_ORIGINS` | Comma-separated **hostnames only** (no scheme, no port — Reverb strips both before comparing) allowed to open a socket. Never `*` in production. | `127.0.0.1,localhost` |
| `VITE_REVERB_APP_KEY` / `VITE_REVERB_HOST` / `VITE_REVERB_PORT` / `VITE_REVERB_SCHEME` | The subset of the above the *browser* needs, exposed through Vite. Never the secret. | mirrors the `REVERB_*` values |

## Single shared Echo client

`resources/js/lib/echo.ts` exports one `getEcho()` — a lazily-created
singleton. No component ever constructs its own `Echo` instance; every
hook and component goes through this one connection.

```ts
resources/js/lib/echo.ts   → getEcho(), disconnectEcho()
resources/js/hooks/useEcho.ts
  usePrivateChannel(channelName, events)   → subscribe/unsubscribe for the life of a component
  useEchoConnectionState(onReconnect?)     → 'initializing' | 'connecting' | 'connected' | 'unavailable' | 'disconnected'
```

**The leading-dot gotcha.** Every `broadcastAs()` in this app returns a
short custom name (`job.status-changed`, not the default
`App\Events\JobStatusChanged`). Echo's default event formatter prepends its
own namespace and replaces every other dot with a backslash unless the
*listener* prefixes the event name with a literal `.` — so
`usePrivateChannel` does this once, internally, for every event name it's
given. Anyone calling `channel.listen()` directly instead of through this
hook needs to remember that dot themselves.

## Channels

Only three patterns exist, in `routes/channels.php` — each mirrors an
authorization rule the equivalent HTTP route already enforces:

| Channel | Who may subscribe | Mirrors |
| --- | --- | --- |
| `private-user.{id}` | Exactly that user. | N/A — a user's own notifications/timer are never shared. |
| `private-project.{id}` | The project's owner (`user_id` match). | `ProjectPolicy::view()` |
| `private-job.{id}` | Any signed-in user, if the job exists. | The Job Detail route itself has no per-job restriction — jobs are shared company-wide. |

A user changing the id in a subscribe request gets a 403 from
`/broadcasting/auth` — this is tested directly against that endpoint in
`tests/Feature/RealtimeChannelAuthTest.php`, including guest requests and
nonexistent ids.

## Events

| Event | Fired from | DB change | Channel | Payload | Frontend consumer | Fallback |
| --- | --- | --- | --- | --- | --- | --- |
| `timer.state-changed` | `TimerService::start/pause/resume/stop/discard` | `timer_sessions` row created/updated/deleted | `user.{userId}` | `{ action, timer: {...} \| null }` — same shape as the `activeTimer` shared prop, no cost fields | `RealtimeUserSync` → reloads `activeTimer` | Timer state is always re-derived from `started_at`/`accumulated_seconds` on every normal page load regardless of socket health |
| `notification.created` | `AppNotificationChannel::send()` (every `Notification` class in the app funnels through this one channel) | `app_notifications` row created | `user.{userId}` | `{ id, type, title, detail, link, createdAt, unreadCount }` | `RealtimeUserSync` → reloads `notifications`, `unreadNotificationCount` | Bell/count are always freshly queried on normal navigation |
| `job.status-changed` | `Job::changeStatus()` | `work_jobs.status` + a `job_status_changes` row | `job.{jobId}` | `{ jobId, name, from, to }` — no cost fields | `JobShow` → reloads `job`, `timeTracking`, `jobCosting` | Job Detail always reflects current DB state on load |
| `job.assignment-changed` | `JobAssignmentController::store/destroy` | `job_assignments` row created/released | `job.{jobId}` | `{ jobId, assignmentId, role, name, action }` | `JobShow` (same reload as above) | same |
| `schedule.changed` | `JobTaskController::settle()` (every task mutation) + `JobScheduleController::update()` | a task/dependency/assignment row, or the schedule's own settings | `job.{jobId}` | `{ jobId, type, description }` — a label for an activity feed, not branched on | `JobShow` (labor/cost widgets) and `JobSchedule` (its own tab props) | Both pages are correct on load regardless |
| `time-entry.logged` | `TimeEntryController::save()` | `time_entries` row created/edited | `job.{jobId}` | `{ jobId, entryId, userId, status, hours, action }` — hours only, never a dollar figure | `JobShow` | same |
| `time-entry.submitted` / `.approved` / `.rejected` | `TimeEntryController::submit/approve/reject` (existing `TimeEntry*` events, now also `ShouldBroadcast`) | `time_entries.status` + a status-change/activity row | `job.{jobId}` | `{ jobId, entryId, userId, status, hours }` | `JobShow` | same |
| `ai-takeoff.status-changed` | `AiJob::booted()` — fires on `created` and on `updated` whenever `status` actually changed, regardless of which of the model's several writers caused it | `ai_jobs` row created/updated | `project.{id}` | `AiRunStatePresenter::present()` — **the exact shape** `ProcessingController`'s long-poll endpoint returns | `Processing.tsx` → applies the payload to its `run` state directly | The existing long-poll chain keeps running underneath; a stale/duplicate push is a no-op since React only re-renders on an actual change |

Deliberately **not** wired: "job created" (no channel exists before the job
does — nobody could be subscribed yet) and plain time-entry `update` beyond
what `time-entry.logged`'s `action` field already distinguishes. Every
payload above was checked, by an explicit test in
`RealtimeBroadcastTest`, to contain no dollar figure — Job Costing values
are **never** broadcast to anyone, on any channel; they exist only in the
authenticated, per-role-redacted HTTP/Inertia response (see
`JobCostSummary::redact()`), which broadcasting cannot vary per-subscriber
anyway.

## Database-first broadcasting

Every broadcastable event implements both `ShouldBroadcast` (queued — it
becomes a `BroadcastEvent` job on the normal queue connection, not sent
inline on the request) and `ShouldDispatchAfterCommit`. The second
interface is what actually enforces "database first": Laravel's event
dispatcher holds the `event()` call itself until the enclosing DB
transaction commits, and drops it entirely if the transaction rolls back —
this is true whether or not the call site happens to be inside an explicit
`DB::transaction()` closure. `ShouldBroadcastNow` (synchronous, unqueued)
is not used anywhere in this app; nothing here has a latency requirement
that justifies bypassing the queue.

## Testing and the `null` driver

`phpunit.xml` sets `BROADCAST_CONNECTION=null` for the whole suite (its
driver's `auth()`/`broadcast()` are deliberate no-ops) so that the rest of
the test suite — which runs with `QUEUE_CONNECTION=sync`, meaning every
queued broadcast job executes **immediately, inline** — never makes a real
network call to a Reverb host that doesn't exist in CI.

`tests/Feature/RealtimeBroadcastTest.php` uses `Event::fake()` to assert the
right event fires (or doesn't) with the right payload, without needing a
real broadcaster at all.

`tests/Feature/RealtimeChannelAuthTest.php` specifically needs *real*
Pusher-protocol authorization logic (channel closures actually evaluated,
a real signed response), so it switches `broadcasting.default` to `reverb`
for just that class. Signing a channel auth response is a local HMAC
operation — no network call — so this is safe. It also has to re-`require
routes/channels.php` after switching, because `Broadcast::channel()`
registers each pattern on whichever driver *instance* was current at boot
(`null`), not on a name — see the comment on that test's `setUp()` for the
full explanation.

## Reconnection and resync

`useEchoConnectionState(onReconnect)` tracks the socket's Pusher-protocol
connection state and calls `onReconnect` on every transition **into**
`connected` after having been connected at least once before — i.e. on a
genuine reconnect, not the initial connection. Every page that subscribes
to a channel passes its own reload function as `onReconnect`, so a
dropped-and-restored connection resyncs exactly the props that page already
knows how to refresh — the same partial reload a live event would have
triggered. Realtime is never assumed to have delivered every event that
happened while disconnected; a reconnect always re-asks the database.

## Duplicate events

The UI never appends anything from a socket payload — every handler is
either a `router.reload()` (re-fetches the authoritative props; a duplicate
reload is just a duplicate no-op fetch) or, for AI Takeoff, a full
`setRun(payload)` replacement of the same shape the poll already uses (not
an array push). There is nothing for a duplicate event to duplicate.

## Mobile compatibility

Built in Phase 9 — see [`docs/mobile-api.md`](mobile-api.md) for the full
contract. It confirms exactly the design this section anticipated: every
broadcast above fires from the **service or model layer**
(`TimerService`, `Job::changeStatus()`, `AiJob`'s own model events), so
`app/Http/Controllers/Api/V1/*` gets the identical broadcast for free by
calling into the same services the web controllers call — no second
broadcast path, no duplicate timer/time-entry table. The two write paths
that had no extracted service at the time this was written
(`JobTaskController`'s task-completion logic and
`TimeEntryController::save()`) were pulled out into
`JobTaskWorkflowService`/`TimeEntryWriteService` specifically so the
mobile API could call the exact same code rather than re-implementing it;
the web controllers were refactored to call the same services, verified
against their existing test coverage to change no observable behavior.

One direction remains intentionally unbuilt: a mobile client subscribing
to Echo/Reverb itself. `/broadcasting/auth` authorizes over the `web`
session-cookie middleware group; a Sanctum-token mobile request has no
session to authenticate a WebSocket with. Phase 9 verified mobile → web
realtime (an action on mobile reaches an already-open web session
instantly); it does not implement web/other-mobile → this-mobile-app
push delivery.

## Production environment

Three long-running processes beyond `php-fpm`/nginx and the existing
scheduler:

```
php artisan reverb:start --host=0.0.0.0 --port=8080
php artisan queue:work --tries=1 --timeout=0
```

(A Supervisor config for both is at
[`deploy/supervisor/breeze.conf`](../deploy/supervisor/breeze.conf).)

### Reverse proxy (Nginx) — HTTPS/WSS

Reverb listens on `REVERB_SERVER_HOST:REVERB_SERVER_PORT` (internal, plain
`ws://`, e.g. `127.0.0.1:8080`) and is never exposed to the internet
directly. Nginx terminates TLS and proxies the WebSocket upgrade to it; the
public `REVERB_HOST`/`REVERB_PORT`/`REVERB_SCHEME` a browser connects to are
the proxy's own HTTPS host/port, not Reverb's:

```nginx
location /app/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 60s;
}
```

With that in place, production `.env` sets:

```
REVERB_SERVER_HOST=127.0.0.1
REVERB_SERVER_PORT=8080
REVERB_HOST=your-domain.com
REVERB_PORT=443
REVERB_SCHEME=https
REVERB_APP_ALLOWED_ORIGINS=your-domain.com
VITE_REVERB_HOST="${REVERB_HOST}"
VITE_REVERB_PORT="${REVERB_PORT}"
VITE_REVERB_SCHEME="${REVERB_SCHEME}"
```

`pusher-js` (which Echo/Reverb use) upgrades `https`/`443` to `wss`
automatically — there's no separate `REVERB_WSS_*` variable to set.

### Restart procedure

```bash
php artisan reverb:restart   # signals the running reverb:start process to gracefully stop; Supervisor restarts it
```

Existing WebSocket connections are closed (clients reconnect
automatically per [Reconnection and resync](#reconnection-and-resync));
nothing is lost because nothing socket-side is ever the only copy of a
fact. Include this in the standard deploy sequence, after
`php artisan queue:restart` and before re-enabling traffic.

### Debug mode

Never run Reverb with `APP_DEBUG=true` in production — the same rule as the
rest of the app; Reverb's own error output otherwise leaks internal state
to a misbehaving client's connection log.
